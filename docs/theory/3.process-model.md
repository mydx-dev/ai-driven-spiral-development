# AI駆動スパイラル開発 — System Engineeringプロセスモデル

本ドキュメントは、AI駆動スパイラル開発におけるSystem側のStandard Processを定義する。

本方式では、AI駆動スパイラルのProcess粒度とISO/IEC/IEEEのProcess粒度を1:1対応させない。

AI駆動スパイラルのProcessは、Coreで定義される次の単位である。

```text
Process
├─ Executor
├─ Artifact(s)
└─ Gate
```

したがって、1 Artifact = 1 Processとはしない。一つのStandard Processの内部で複数のISO由来Engineering Process / Activityを適用してよい。

ISO/IEC/IEEEへ整合させる対象は、Standard Processの工程分割そのものではなく、各Artifactの意味・構造・性質と、それを導出するEngineering責任である。

基礎とする規格は以下である。

- ISO/IEC/IEEE 15288:2023 — System life cycle processes
- ISO/IEC/IEEE 29148:2018 — Requirements engineering
- ISO/IEC/IEEE 42010:2022 — Architecture description
- ISO/IEC/IEEE 15289:2019 — Content of life-cycle information items

ISO/IEC/IEEE 42010:2022はArchitecture Descriptionのstructure / expressionの基礎として使用し、architecting process自体を規定する規格として扱わない。

---

# 1. 要求定義

## 1.1 位置付け

`要求定義` は、StakeholderがSystem of Interestに対して必要としているCapability、期待、制約、利用状況を明確にし、StRSへ反映するStandard Processである。

Engineering責任としては、ISO/IEC/IEEE 15288:2023のStakeholder Needs and Requirements Definitionと、ISO/IEC/IEEE 29148:2018のRequirements Engineeringを基礎とする。

中心的な問いは、

> **Stakeholderは何を必要としているか**

である。

## 1.2 Output Artifact — StRS

本Processは `StRS` を生成・更新する。

StRSは少なくとも以下を表現する。

- Stakeholder
- Stakeholder Needs / Requirements
- Purpose / Scope
- Business / Operational Context
- Constraints
- Scenarios
- Requirement source
- Traceability
- Unresolved items

StRSはSystem内部構造やSoftware実装方法を定義しない。

## 1.3 Gate

GateはStRSについて、当該Cycleで必要なStakeholder Requirements情報が定義・判断済みであり、次の`システム要件定義`が開始可能であることを確認する。

GateはAI駆動スパイラル独自の完了判定であり、ISO/IEC/IEEEがこのGateを規定しているという意味ではない。

---

# 2. システム要件定義

## 2.1 位置付け

`システム要件定義` は、Stakeholder RequirementsからSystem Requirementsを定義し、さらにSystem Architecture DescriptionによってSystem構造と責任割当を明確にするStandard Processである。

この一つのProcess内部で、少なくとも次のEngineering責任を扱う。

```text
システム要件定義 Process
├─ System Requirements Definition相当のEngineering
│   └─ SyRS
├─ Architecture Definition [System]相当のEngineering
│   └─ System Architecture Description
├─ Executor
└─ Gate
```

この束ね方はAI駆動スパイラル独自であり、ISO/IEC/IEEEがSyRSとSystem Architecture Descriptionを一つの工程へ束ねることを要求しているわけではない。

## 2.2 SyRS

SyRSはSystem of Interest全体が満たすべきRequirementsを表現する。

ISO/IEC/IEEE 29148:2018のRequirements Engineeringを基礎とする。

少なくとも以下を扱う。

- System functional requirements
- System quality requirements
- External interface requirements
- System constraints
- Assumptions / dependencies
- Verification consideration
- StRSとのtraceability

SyRSはSoftware Requirementではない。

## 2.3 System Architecture Description

System Architecture Descriptionは、SyRSを満たすためのSystem構造を表現するStandard Artifactである。

Architectureを導出するEngineering責任はISO/IEC/IEEE 15288:2023のArchitecture Definition [System]を基礎とし、Architecture Descriptionのstructure / expressionはISO/IEC/IEEE 42010:2022を基準とする。

少なくとも以下を表現する。

- System boundary
- System Elements
- Element responsibilities
- Element relationships
- Interfaces
- Architecture decisions / rationale
- System RequirementsからSystem Elementsへのallocation / traceability

Requirement Allocationを独立したStandard Processまたは独立したStandard Artifactとして扱わない。

```text
SyRS Requirement
        ↓ allocation / traceability
System Architecture Description
        ↓
System Element
```

Softwareへ割り当てられたSystem Requirementsのみが、後続の`ソフトウェア要件定義`の直接入力となる。

## 2.4 Gate

GateはSyRSとSystem Architecture Descriptionを一体として確認する。

少なくとも以下を満たす必要がある。

- 当該CycleのSystem Requirementsが定義・判断済みである
- StRS → SyRSのtraceabilityが存在する
- System boundaryとSystem Elementsが識別されている
- 必要なrelationship / interfaceがArchitecture上で表現されている
- 当該CycleのSystem RequirementsにSystem Elementへのallocation / traceabilityが存在する
- Softwareへ割り当てられた責任が識別可能である
- 後続のSoftware Requirements導出に利用可能な状態である

---

# 3. System側Traceability

System側では最低限、以下のTraceabilityを保持する。

```text
Stakeholder Need / Requirement
        ↓
       StRS
        ↓
System Requirement
        ↓
       SyRS
        ↓
System Architecture Description
        ↓ allocation / traceability
System Element
```

System Architecture DescriptionはRequirement Allocationの責任を内包するが、RequirementそのものとArchitectureを混同しない。

---

# 4. ProcessとISO Processの関係

AI駆動スパイラルのStandard Process名は利用者・実行者が理解しやすい日本語名とし、ISO Process名を逐語的にStandard Process名へコピーしない。

```text
AI駆動スパイラル
要求定義
  ↓
StRS

Engineering responsibility
Stakeholder Needs and Requirements Definition / Requirements Engineering
```

```text
AI駆動スパイラル
システム要件定義
  ├─ SyRS
  └─ System Architecture Description

Engineering responsibilities
System Requirements Definition
Architecture Definition [System]
```

Process粒度とISO Process粒度は別物である。
