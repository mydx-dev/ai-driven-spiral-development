# AI駆動スパイラル開発 — サイクルモデル

## 1. サイクル

サイクルは、AI駆動スパイラル開発における開発の反復単位である。

一つのサイクルは複数のプロセスによって構成される。

```text
Cycle N
│
├ Process 1
├ Process 2
├ Process 3
├ ...
│
└ Feedback
      │
      ├─ 次の要求なし → Cycle終了
      │
      └─ 次の要求あり → Cycle N+1
```

サイクルの目的は、要求を一度で完全に確定することではない。

成果物を生成し、ユーザーによる知覚と評価を通じて得られたフィードバックを、必要に応じて次のサイクルへ接続する。

この反復によって要求の解像度を高める。

---

## 2. プロセス

プロセスは、サイクルを構成する工程の単位である。

一つのプロセスは、

- プロセス実行者
- アーティファクト
- プロセスゲート

によって構成される。

```text
┌──────────────── Process ────────────────┐
│                                         │
│  プロセス実行者 ──→ アーティファクト ←── プロセスゲート
│                                         │
└─────────────────────────────────────────┘
                                           │
                                           │ 進行可能
                                           ↓
                                  次のプロセス実行者
```

プロセス実行者によるアーティファクトの生成・更新と、プロセスゲートによる状態判定までを、一つのプロセスとして扱う。

---

## 3. アーティファクト

アーティファクトは、プロセス単位の成果物である。

プロセス実行者は、割り当てられたアーティファクトを生成または更新する。

アーティファクトはプロセスゲートから観測可能でなければならない。

```text
プロセス実行者
      │
      │ 生成・更新
      ↓
アーティファクト
      ↑
      │ 観測
プロセスゲート
```

アーティファクトは単なる成果物であると同時に、プロセスの進行状態を外部から観測するための境界でもある。

---

## 4. プロセス実行者

プロセス実行者は、アーティファクトを生成または更新する主体である。

その責務は、

> **割り当てられたアーティファクトを生成・更新すること**

に限定する。

プロセス実行者は、原則として以下を判断しない。

- 自身のプロセスが完了したか
- 次のプロセスへ進行してよいか
- 次のプロセス実行者が誰か
- 次のプロセス実行者をいつ起動するか

したがって、

```text
アーティファクト生成
= プロセス実行者の責務

プロセス進行
= プロセス実行者の責務ではない
```

とする。

これにより、アーティファクトを生成する主体の主観と、開発プロセスの制御を分離する。

---

## 5. プロセスゲート

プロセスゲートは、プロセス実行者から通知された意味的完了を契機として、アーティファクトの状態を観測し、構造的完了を判定する仕組みである。

```text
プロセス実行者
      │
      │ 意味的完了を通知
      ↓
スパイラル
      │
      ↓
プロセスゲート
      │
      │ アーティファクトを観測
      ↓
構造的完了を判定
      │
      ├─ 未完了 → 現プロセスを継続
      │
      └─ 完了
              │
              ↓
      次のプロセス実行者を起動
```

プロセス実行者は、自身の責務において必要な作業を終えたと判断した時点で、意味的完了を通知する。

ただし、この通知そのものをプロセスの完了とはみなさない。

プロセスゲートは、実際に生成・更新されたアーティファクトを観測し、プロセスが次工程へ進行可能な状態にあるかを構造的に判定する。

したがって、

```text
意味的完了
= プロセス実行者による完了判断

構造的完了
= プロセスゲートによる観測可能な状態に基づく完了判定
```

とする。

意味的完了はプロセスゲートを起動する契機であり、構造的完了は次プロセスへの進行条件である。

---

## 6. 意味的完了と構造的完了

AI駆動スパイラル開発では、プロセスの完了を二つに分離する。

### 意味的完了

意味的完了とは、

> **プロセス実行者が、自身に割り当てられた責務を完了したと判断した状態**

である。

プロセス実行者は、人間、AI Agent、その他の自律的実行主体であってよい。

これらの主体は、入力された情報やコンテキストを解釈しながらアーティファクトを生成するため、その判断には非決定性を含み得る。

プロセス実行者は、意味的完了に到達したと判断すると、その事実をイベントとしてスパイラルへ通知する。

```text
プロセス実行者
      │
      │ Artifact生成・更新
      ↓
意味的完了
      │
      │ Event
      ↓
Spiral
```

ただし、意味的完了は次プロセスへの進行を保証しない。

---

### 構造的完了

構造的完了とは、

> **プロセスのアーティファクトが、次工程へ進行するために必要な観測可能な条件を満たしている状態**

である。

構造的完了はプロセスゲートによって判定する。

例えば、

- 必要なアーティファクトが存在する
- 必須情報が記録されている
- 必要な関連が成立している
- 必要な状態遷移が完了している
- 必要な検証結果が存在する

など、アーティファクトから観測可能な条件を用いる。

```text
Semantic Completion Event
          │
          ↓
      Process Gate
          │
          │ Artifactを観測
          ↓
 Structural Completion
      │           │
    false        true
      │           │
      ↓           ↓
 現Process継続   次Process起動
```

---

### 非決定的生成と決定的制御

AI Agentを含むプロセス実行者によるアーティファクト生成は、非決定的であってよい。

一方、プロセス進行の最終判定は、可能な限り観測可能なアーティファクト状態に基づく構造的判定とする。

したがって、

```text
生成
= 非決定性を許容

意味的完了
= 実行主体による判断

構造的完了
= プロセスゲートによる判定

進行
= 構造的完了によって決定
```

という責務分離を行う。

これにより、

> **非決定的な実行主体に生成の自由度を与えながら、プロセス進行は観測可能な状態によって制御する。**

ことができる。

---

## 7. プロセスの連鎖

サイクルは、プロセスの連鎖によって構成される。

```text
[実行者₁ → アーティファクト₁ ← ゲート₁]
   ┌──────────────────────────┘
   ↓
[実行者₂ → アーティファクト₂ ← ゲート₂]
   ┌──────────────────────────┘
   ↓
[実行者₃ → アーティファクト₃ ← ゲート₃]
   ┌──────────────────────────┘
   ↓
                            ...
```

前のプロセスゲートが進行可能と判定することで、次のプロセス実行者が起動する。

したがって、プロセス間を直接接続するのはプロセス実行者ではない。

```text
実行者₁
↓
実行者₂
↓
実行者₃
```

ではなく、

```text
実行者₁
↓
アーティファクト₁
↑
ゲート₁
↓
実行者₂
↓
アーティファクト₂
↑
ゲート₂
↓
実行者₃
```

という構造を取る。

## 8. サイクルからスパイラルへ

サイクルの最終的な評価によって新しい要求が得られた場合、その要求を次のサイクルへ入力する。

```text
Cycle N
│
├ Process
├ Process
├ Process
│
└ 評価
    ↓
フィードバック
    │
    ├─ 新しい要求なし
    │      ↓
    │   開発終了
    │
    └─ 新しい要求あり
           ↓
        Cycle N+1
```

したがって、

```text
プロセスの連鎖
↓
サイクル

サイクルの反復
↓
スパイラル
```

という関係になる。

AI駆動スパイラル開発は、このサイクルを繰り返すことで、成果物に対するユーザーの知覚と評価を継続的に次の開発へ反映する。

---

## 9. サイクルモデル

以上をまとめると、AI駆動スパイラル開発の基本構造は次のようになる。

```text
┌──────────────────── Cycle N ────────────────────┐
│                                                 │
│  [実行者₁ → Artifact₁ ← Gate₁]                   │
│     ┌───────────────────┘                       │
│     ↓                       　　　　　　　　　　　　│
│  [実行者₂ → Artifact₂ ← Gate₂]                   │
│     ┌───────────────────┘                       │
│     ↓                                           │
│  [実行者₃ → Artifact₃ ← Gate₃]                   │
│     ┌───────────────────┘                       │
│     ↓                                           │
│                        ...                      │
│                         │                       │
│                         ↓                       │
│                    フィードバック                  │
│                                                 │
└─────────────────────────┬───────────────────────┘
                          │
              ┌───────────┴───────────┐
              │                       │
          要求なし                  要求あり
              │                       │
              ↓                       ↓
             終了                  Cycle N+1
```

このモデルにおいて、

> **プロセス実行者はアーティファクトを作り、プロセスゲートはアーティファクトを見て次のプロセス実行者を呼ぶ。**

これをサイクル全体に連鎖させ、フィードバックによって次のサイクルへ接続することが、AI駆動スパイラル開発の基本的な実行構造である。
