# AI駆動スパイラル開発 — サイクルモデル

## 1. サイクル

サイクルは、AI駆動スパイラル開発における開発の反復単位である。

一つのサイクルは複数のプロセスによって構成される。

```text
Cycle N
│
├ Process 1
├ Process 2
├ Process 3
├ ...
│
└ Feedback
      │
      ├─ 次の要求なし → Cycle終了
      │
      └─ 次の要求あり → Cycle N+1
```

サイクルの目的は、要求を一度で完全に確定することではない。

成果物を生成し、ユーザーによる知覚と評価を通じて得られたフィードバックを、必要に応じて次のサイクルへ接続する。

この反復によって要求の解像度を高める。

---

## 2. プロセス

プロセスは、サイクルを構成する工程の単位である。

一つのプロセスは、

- プロセス実行者
- アーティファクト
- プロセスゲート

によって構成される。

```text
┌──────────────── Process ────────────────┐
│                                         │
│  プロセス実行者 ──→ アーティファクト ←── プロセスゲート
│                                         │
└─────────────────────────────────────────┘
                                           │
                                           │ 進行可能
                                           ↓
                                  次のプロセス実行者
```

プロセス実行者によるアーティファクトの生成・更新と、プロセスゲートによる状態判定までを、一つのプロセスとして扱う。

---

## 3. アーティファクト

アーティファクトは、プロセス単位の成果物である。

プロセス実行者は、割り当てられたアーティファクトを生成または更新する。

アーティファクトはプロセスゲートから観測可能でなければならない。

```text
プロセス実行者
      │
      │ 生成・更新
      ↓
アーティファクト
      ↑
      │ 観測
プロセスゲート
```

アーティファクトは単なる成果物であると同時に、プロセスの進行状態を外部から観測するための境界でもある。

---

## 4. プロセス実行者

プロセス実行者は、アーティファクトを生成または更新する主体である。

その責務は、

> **割り当てられたアーティファクトを生成・更新すること**

に限定する。

プロセス実行者は、原則として以下を判断しない。

- 自身のプロセスが完了したか
- 次のプロセスへ進行してよいか
- 次のプロセス実行者が誰か
- 次のプロセス実行者をいつ起動するか

したがって、

```text
アーティファクト生成
= プロセス実行者の責務

プロセス進行
= プロセス実行者の責務ではない
```

とする。

これにより、アーティファクトを生成する主体の主観と、開発プロセスの制御を分離する。

---

## 5. プロセスゲート

プロセスゲートは、アーティファクトの状態を観測し、次のプロセスへ進行可能かを判定する仕組みである。

```text
アーティファクト
      ↑
      │ 観測
プロセスゲート
      │
      ├─ 進行不可 → 状態変化を待つ
      │
      └─ 進行可能
              │
              ↓
      次のプロセス実行者を起動
```

プロセスゲートは、例えば、

- アーティファクトの状態を監視する
- アーティファクトの状態変化をイベントとして受け取る

ことによって判定を開始する。

具体的な観測方法には依存しない。

重要なのは、

> **プロセス実行者の自己申告ではなく、アーティファクトの観測可能な状態によって進行可否を判定すること**

である。

進行可能と判定した場合、プロセスゲートは次のプロセス実行者を起動する。

---

## 6. プロセスの連鎖

サイクルは、プロセスの連鎖によって構成される。

```text
[実行者₁ → アーティファクト₁ ← ゲート₁]
   ┌──────────────────────────┘
   ↓
[実行者₂ → アーティファクト₂ ← ゲート₂]
   ┌──────────────────────────┘
   ↓
[実行者₃ → アーティファクト₃ ← ゲート₃]
   ┌──────────────────────────┘
   ↓
                            ...
```

前のプロセスゲートが進行可能と判定することで、次のプロセス実行者が起動する。

したがって、プロセス間を直接接続するのはプロセス実行者ではない。

```text
実行者₁
↓
実行者₂
↓
実行者₃
```

ではなく、

```text
実行者₁
↓
アーティファクト₁
↑
ゲート₁
↓
実行者₂
↓
アーティファクト₂
↑
ゲート₂
↓
実行者₃
```

という構造を取る。

---

## 7. 生成と制御の分離

このサイクルモデルでは、自律性を二つに分離する。

### 生成の自律性

プロセス実行者は、割り当てられた責務の範囲で自律的にアーティファクトを生成する。

### 制御の自律性

プロセスゲートは、アーティファクトの状態に基づいて自律的に進行可否を判定し、必要に応じて次のプロセス実行者を起動する。

```text
プロセス実行者
      │
      │ 生成
      ↓
アーティファクト
      ↑
      │ 判定
プロセスゲート
      │
      │ 制御
      ↓
次のプロセス実行者
```

これによって、

> **アーティファクトを作る主体と、開発プロセスを進行させる仕組みを分離する。**

AI Agentのような非決定的な主体をプロセス実行者として利用する場合でも、その主体自身にプロセス全体の制御を委ねる必要がない。

---

## 8. サイクルからスパイラルへ

サイクルの最終的な評価によって新しい要求が得られた場合、その要求を次のサイクルへ入力する。

```text
Cycle N
│
├ Process
├ Process
├ Process
│
└ 評価
    ↓
フィードバック
    │
    ├─ 新しい要求なし
    │      ↓
    │   開発終了
    │
    └─ 新しい要求あり
           ↓
        Cycle N+1
```

したがって、

```text
プロセスの連鎖
↓
サイクル

サイクルの反復
↓
スパイラル
```

という関係になる。

AI駆動スパイラル開発は、このサイクルを繰り返すことで、成果物に対するユーザーの知覚と評価を継続的に次の開発へ反映する。

---

## 9. サイクルモデル

以上をまとめると、AI駆動スパイラル開発の基本構造は次のようになる。

```text
┌──────────────────── Cycle N ────────────────────┐
│                                                 │
│  [実行者₁ → Artifact₁ ← Gate₁]                   │
│     ┌───────────────────┘                       │
│     ↓                       　　　　　　　　　　　　│
│  [実行者₂ → Artifact₂ ← Gate₂]                   │
│     ┌───────────────────┘                       │
│     ↓                                           │
│  [実行者₃ → Artifact₃ ← Gate₃]                   │
│     ┌───────────────────┘                       │
│     ↓                                           │
│                        ...                      │
│                         │                       │
│                         ↓                       │
│                    フィードバック                  │
│                                                 │
└─────────────────────────┬───────────────────────┘
                          │
              ┌───────────┴───────────┐
              │                       │
          要求なし                  要求あり
              │                       │
              ↓                       ↓
             終了                  Cycle N+1
```

このモデルにおいて、

> **プロセス実行者はアーティファクトを作り、プロセスゲートはアーティファクトを見て次のプロセス実行者を呼ぶ。**

これをサイクル全体に連鎖させ、フィードバックによって次のサイクルへ接続することが、AI駆動スパイラル開発の基本的な実行構造である。
